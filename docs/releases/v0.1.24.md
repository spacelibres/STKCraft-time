# stkcraft-time 0.1.24

Release date: 2026-11-12

Documentation release. There is no library, kernel-format or numerical
change.

## Branding and links in every guide

`docs/API.md`, `docs/MCP.md` and `docs/TIME_CONTRACT.md` now begin with the
project mark and a link row:

- crates.io — <https://crates.io/crates/stkcraft-time>
- API reference — <https://docs.rs/stkcraft-time>
- source — <https://github.com/spacelibres/STKCraft-time>
- wiki — <https://github.com/spacelibres/STKCraft-time/wiki>
- STKCraft — <https://www.stkcraft.com>

A reader who arrives at a single page can reach the registry, the generated
API reference and the wiki without going back to the README.

## Wiki

The wiki now carries the brand and the registry links on every page:

| Location | Content |
|---|---|
| `Home` | SVG mark, crates.io / docs.rs / downloads / release / CI / license / MSRV / no_std badges, crate links |
| `_Sidebar.md` | raster mark linked to `Home`, navigation, crates.io and docs.rs badges, project links |
| `_Footer.md` | source, crates.io, API reference, releases, issues, STKCraft |

The SVG is used for the large mark because it stays sharp at any width; the
sidebar uses the raster mark because it is repeated on every page and is
roughly one eighth of the file size. Both come from the same brand asset in
`STKCraft_web`.

## Why the README keeps the raster mark

The README is rendered on crates.io, GitHub and docs.rs, and crates.io
sanitises embedded HTML. The raster `<img>` is the form that renders
everywhere without relying on `<picture>`/`srcset` support. The crate page
therefore keeps the PNG mark, while the wiki uses the SVG where the
renderer is known to support it.
