# stkcraft-time 0.1.7

Release date: 2026-11-11

This is a correctness and hardening release. It fixes every finding in the
2026-11-11 audit: SCLK offsets, checked epoch/duration arithmetic, MCP
robustness, formatting carry, UT1 boundaries and gaps, kernel validation,
continuous ticks, JSON-RPC handling, `TimeSeries` extremes and TLS in the
coefficient generator.

There are no intentional time-scale definition changes. Results change
only where the previous behaviour was wrong.

## Correctness fixes

- **SCLK offsets** now follow NAIF: encode as `field - offset`, decode as
  `encoded + offset`. A Voyager-like third field with offset 1 maps
  displayed `[0, 0, 1]` to tick 0.
- **Epoch arithmetic** uses checked i128 totals. `from_parts` and
  `from_tai_seconds` panic on overflow or non-finite input instead of
  wrapping or producing zero. `checked_from_parts`,
  `checked_from_tai_seconds`, `checked_add` and `checked_sub` are
  available for untrusted input.
- **MCP precision** is limited to `0..=9`; tool panics are caught per
  request, so one bad call cannot terminate the server.
- **Formatting** rounds with carry into minutes and days. Precision is
  clamped to nanoseconds. `9.9999` no longer becomes `010.000`, and
  `59.9999` no longer becomes a nonexistent `60.000`.
- **`etcal`** splits ET into whole days and seconds before formatting, so
  a microsecond at J2000 is preserved.
- **UT1 inverse conversion** now works at the first EOP day. The initial
  fixed-point guess is clamped to the EOP-supported interval.
- **UT1 gaps across leap seconds** are handled by interpolating continuous
  `UT1 - TAI` instead of raw `UT1 - UTC`. Sparse samples no longer
  reintroduce a ~0.25 s step error.
- **Duration checked operations** use i128 totals and accept representable
  extrema, including `a.checked_sub(a) == Some(ZERO)`.
- **Non-finite values** are rejected at public numeric entry points; EOP
  queries reject NaN instead of returning the first row.
- **LSK/SCLK validation** reads all data blocks, validates dates, rejects
  non-finite constants, requires increasing ticks/seconds and positive
  rates, and checks partition arrays.
- **Partitioned SCLK** field/string conversion returns
  `SclkPartitionsUnsupported` instead of silently ignoring partition
  offsets. Encoded ticks↔ET/TAI remain available.
- **Continuous SCLK ticks** are accepted by MCP; optional fields and clock
  strings are `null` for non-integral ticks.
- **JSON-RPC** invalid requests receive `-32600`; the server advertises
  only protocol version `2024-11-05`.
- **`TimeSeries`** uses checked cursor advancement, so the last
  representable epoch is delivered before the iterator ends.
- **`tools/gen_dtdb_table.py`** verifies TLS by default, pins the ERFA
  commit and SHA-256, and requires an explicit `--insecure` opt-out.

## Action required

- Callers that pass overflow or non-finite values to `Epoch::from_parts`
  or `Epoch::from_tai_seconds` now get a panic instead of a wrapped or
  zero epoch. Switch untrusted input to the `checked_*` variants.
- Kernels with nonzero `SCLK01_OFFSETS` now produce corrected tick values.
  Existing results for such clocks should be rechecked.
- Partitioned SCLK kernels now reject field/string conversion. Use
  encoded ticks↔ET/TAI, or apply the partitions in the caller.
- Code that matches `TimeError` exhaustively must handle the new
  `SclkPartitionsUnsupported` variant.

## Install

The crate is not yet on crates.io. Use the tagged repository:

```toml
[dependencies]
stkcraft-time = { git = "https://github.com/spacelibres/STKCraft-time", tag = "v0.1.7" }
```

Or:

```sh
cargo add --git https://github.com/spacelibres/STKCraft-time --tag v0.1.7 stkcraft-time
```

For `no_std` plus `alloc`:

```toml
stkcraft-time = { git = "https://github.com/spacelibres/STKCraft-time", tag = "v0.1.7", default-features = false }
```

`tdb-compare`, `wgc-compare`, `README.md`, `LICENSE` and `CHANGELOG.md`.

## Compatibility

- MSRV: Rust 1.75.
- `no_std` with `alloc` is supported with `default-features = false`.
- The MCP server requires `std` and the `mcp` feature.
- No intentional breaking change to time-scale definitions. The SCLK
  offset fix changes previously incorrect results for nonzero-offset
  clocks.

## Security

Report vulnerabilities through the private advisory link in
[`SECURITY.md`](https://github.com/spacelibres/STKCraft-time/blob/main/SECURITY.md).
The crate forbids unsafe code and performs no network I/O.
