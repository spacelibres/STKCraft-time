# stkcraft-time 0.1.14

Release date: 2026-11-11

This release fixes the crates.io check in the `Release` workflow. There is
no library change.

## What went wrong in 0.1.13

The `publish-crates` job asked the crates.io API whether the version
already existed. The request carried no `User-Agent`, and crates.io
answers `403` to such requests instead of `404`. The job treated anything
that was not `200` as "not published" and ran `cargo publish`, which
failed with:

```
error: crate stkcraft-time@0.1.13 already exists on crates.io index
```

## Fix

The lookup now sends an explicit `User-Agent`, logs the status it saw, and
publishes only when crates.io answers `404`:

| Status | Action |
|---|---|
| `200` | Already published; the job succeeds without uploading. |
| `404` | Publish with `cargo publish --locked`. |
| anything else | Fail loudly instead of guessing. |

Together with the existing secret check, the job now behaves as intended:
it skips when `CARGO_REGISTRY_TOKEN` is absent, skips when the version
already exists, and publishes exactly once otherwise.
