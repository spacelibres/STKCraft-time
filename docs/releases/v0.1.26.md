# stkcraft-time 0.1.26

Release date: 2026-11-12

Hardening release for the 0.1.25 kernel-date parser. No API change and no
numeric change to any accepted literal.

## Two malformed forms now fail

`kernel_date::parse_kernel_date` accepted two inputs it should have
rejected:

| Input | Previous result | Now |
|---|---|---|
| `@01-2000-02` | `2000-01-02` | `KernelDateUnsupported` |
| `@2000-JAN-01-12:00:.` | `00:00:00` seconds | `KernelDateUnsupported` |

A numeric year in the middle field has no N0067 meaning: it would force a
month-day-year reinterpretation that NAIF does not define. A
fractional-second field with no digits has no numeric value at all, so
treating it as exactly zero hid a malformed literal.

Both cases are now covered by `tests/kernel_dates.rs`. Silent
reinterpretation is the failure mode this parser exists to prevent, so it
must reject rather than guess.

## Compatibility

`kernel_date::parse_kernel_date`, `KernelDate`, and
`TimeError::KernelDateUnsupported` are unchanged. Only inputs that were
previously misread are affected.
