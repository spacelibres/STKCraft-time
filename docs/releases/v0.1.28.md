# stkcraft-time 0.1.28

Release date: 2026-11-12

The kernel-date resolver now accepts the 99 native-valid literals reported
in issue #2, including the mixed-delimiter epoch in the actual RSSD frame
kernel. It preserves N0067 year-token precedence, short-year expansion,
month prefixes, calendar/clock overflow, Julian dates and exercised ISO
ordinal forms. Bare `@2000-060` remains a native rejection.

The independent native corpus has 416 unique inputs: 345 numeric results
and 71 rejected inputs. Every numeric result is compared by IEEE-754 bits;
all rejected inputs require `KernelDateUnsupported`. No original input or
native output is adjusted. The seven fractional-second counterexamples
and original eleven-literal checkpoint are retained.

Old tests incorrectly described eight native-valid forms as malformed.
Those same inputs are now checked against their independently captured
native values. A component grid additionally exposed and corrected seventeen
over-acceptance cases before release. Original red/green evidence is retained.

Public signatures are unchanged. Short-year interpretation follows native
token rules: `@19-JAN-87` denotes 2019-03-28, not an inferred 1987 date.
No UTC/time-scale conversion, LSK fallback or scientific model is introduced.
See [the exact scope](../reference/KERNEL_DATE_GRAMMAR.md).

Full TPARSE grammar conformance remains unclaimed. Era/zone modifiers and
mutable year-expansion contexts remain outside the resolver. All repository
verification and publication checks remain required before acceptance.
