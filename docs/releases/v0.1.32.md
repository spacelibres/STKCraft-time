# stkcraft-time 0.1.32

Release date: 2026-11-12

This release adds nominal BeiDou time and complete Python and
WASM/JavaScript/TypeScript adapter packages around the existing Rust core.
The core dependency graph, Rust 1.75/no_std contract and existing public
TimeScale enum are preserved. A normalized source comparison confirms that
all 29 pre-existing Rust implementation files other than lib.rs are unchanged;
lib.rs only adds the Bdt module/export. Existing Geocalc calls are preserved.

## BeiDou coordinates

The additive Bdt type stores exact integer seconds/nanoseconds from
2006-01-01 00:00:00 UTC. It supports checked construction, full signed weeks,
TAI Epoch, UTC with supplied LSK/policy and checked NAIF ET. Independent
ERFA fixtures cover the origin, leap labels and fractional boundaries.
Nominal TAI/BDT and GPS/BDT calendar offsets are distinguished from elapsed
counts with different origins. Physical satellite/broadcast clock corrections
are not implemented or inferred from integer storage precision.

## Language interfaces

Independent binding workspaces provide owned immutable kernels and time
objects, explicit NaifEt versus scientific IauTdb, exact Python int / JS bigint
transport, EOP/UT1, SCLK, formatting, model functions, batches, serialization
and lazy series. Public inventories classify 231 declarations, including
nested public raw NAIF context types. Compatibility namespaces delegate
literal legacy Rust routes; checked TimeContext remains the recommended
geometry entry point.

Foreign input guards reject oversized integers before narrowing, finite
inputs whose evaluation overflows, non-finite results, unsafe civil-year
narrowing, calendar carry, invalid schemas, disposed handles and invalid
model combinations. Batches preserve scalar error semantics and identify the
failing index. Adapter-specific conservative bounds and unsupported runtime
claims are documented rather than silently broadening the scientific model.

See [language support and validation](../BINDINGS.md), per-package inventories
and verification records. The npm name @stkcraft/time remains conditional on
registry namespace ownership. Registry installation is only available after
successful registry publication; absence of PyPI/npm credentials is reported
as a publication blocker. GitHub Release artifacts remain independently
installable without assuming registry availability.

## Verification

- All twelve native release commands passed: 184 default tests, 197 with MCP,
  and 201 release-mode tests including doctests; Clippy, rustdoc, Rust1.75,
  wasm32 and thumbv7em no_std builds passed.
- All 14 BDT tests passed with and without default features; 28 reference rows
  regenerate from independent ERFA. Checked civil range and active-offset
  arithmetic guards were independently reviewed.
- All 253 Python installed-wheel and external rebuilt-sdist tests pass, covering
  the existing CSPICE/ERFA corpora, exact integer limits, hostile custom data, model/error
  contracts and all declaration mappings. Types, licenses and bundled core
  source identities are verified; strict mypy checks the installed interface.
- Actual WASM runs in Node and Chromium pass 79,520 assertions each, including
  910 checked UTC and 10,871 SCLK rows bit for bit, plus ERFA models, boundary
  errors, 60,000 Date labels,
  950 ERFA coordinate rows, module Workers, TypeScript, bundling and an
  independently installed tarball. Coordinate reference differences remain
  below the existing gates (TCG < 5e-7 seconds, TT/TDB/TCB < 1e-6 seconds);
  the measured maximum is 2.384185791015625e-7 seconds.
- Isolated Geocalc validation passes all 42 same-ET/UTC/numeric-TAI state rows
  with zero measured ET, position and velocity differences in that sample.
  Its six CK tests also pass: 32,622 encoded-pointing queries, 420 frame rows,
  42 time/tick references and scalar-clock acceptance.
- The Cortex-M4 example passes three host CSPICE bit checks and three civil
  roundtrips and links a complete ARM firmware. Its DWT harness has not been
  executed on a board; no hardware cycle/latency measurement is claimed.

Tag publication requires the language CI matrix in addition to native
builds. Combined binaries, wheels, source distribution and npm tarball are
attached with SHA256SUMS.txt. Optional PyPI/npm publication requires its own
configured credentials and successful publication confirmation.

All numerical agreement statements concern the tested inputs and runtimes,
not physical clock accuracy, every possible kernel or flight qualification.
The developing Geocalc source and lockfile are not edited by this task.
