# stkcraft-time 0.1.15

Release date: 2026-11-11

This release adds a build-time guard that keeps every published version
reference exact. There is no library change.

## Version references cannot drift any more

`tests/version_sync.rs` compares the crate version in `Cargo.toml` with
every version mentioned in the files that ship the release:

| File | Checked |
|---|---|
| `README.md` | every `0.1.x` occurrence, plus the three install snippets |
| `docs/API.md` | every `0.1.x` occurrence, plus the install snippets |
| `CITATION.cff` | `version` field |
| `.github/ISSUE_TEMPLATE/bug_report.yml` | version placeholder |

The install snippets must pin the exact release (`stkcraft-time =
"0.1.15"`, `version = "0.1.15"`, `tag = "v0.1.15"`). A range such as
`"0.1"` fails the test, so the documented dependency always names the
version that was actually released.

A mismatch fails `cargo test` with the file and the stale value, for
example:

```
README.md references 0.1.13, but the crate version is 0.1.14
```

`CHANGELOG.md` and `docs/releases/` are intentionally excluded because
they record history.

- 108 tests by default, 120 with the `mcp` feature, all passing
- The guard was checked in both directions: mutating the README to the
  previous version fails the suite, restoring it passes

  sets), `no_std`, `wasm32-unknown-unknown`, `thumbv7em-none-eabi`
- release build and release tests, MSRV 1.75, rustdoc with `-D warnings`
