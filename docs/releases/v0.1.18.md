# stkcraft-time 0.1.18

Release date: 2026-11-11

This release fixes two time-library blockers found during CK attitude
integration: legal SCLK scalars were rejected, and TDT clock conversion
introduced rounding differences that could fail a zero-tolerance query.

## Corrected behavior

- Numeric SCLK assignments accept both a scalar and a parenthesized value,
  including one-field moduli, offsets and partition bounds. Numeric kernel
  integer retrieval accepts decimal/exponent notation with native rounding;
  formatted clock-string fields retain their strict integer validation.
- TDT clocks convert original parallel TT directly to ET with N0067 UNITIM
  arithmetic. The inverse converts ET directly to TT with three native
  iterations. Neither f64 path passes through an integer Epoch or an origin
  shift. Explicit TAI/Epoch APIs retain their documented quantization.
- Affine clock conversion uses native reciprocal-rate evaluation and reverse
  modulus accumulation, including nonbinary tick scales.

The former 0.9313225746 ns and larger 119.2092896 ns counterexamples are
covered by independent CSPICE regressions. No result-specific correction,
time clamp, CK search-tolerance increase or scientific-model substitution
is used.

## Reproducible verification

- `tests/golden/sclk.csv` contains 10,871 independent SCT2E/SCE2C reference
  cases generated by `tools/gen_sclk_golden.py` using SpiceyPy 8.3.0 and
  CSPICE N0067. Original NASA MRO and ESA JUICE kernel sources and hashes
  are recorded in `tests/kernels/README.md`.
- The dense comparison uses 561,303 MRO and 546,249 JUICE input queries,
  including coefficient neighbors, mission-date grids, random queries and
  floating-point cancellation boundaries. Both directions are compared
  separately with native entry points in debug and release modes; both
  directions matched bit for bit in each profile.
- An isolated Geocalc client checks a real MRO HGA CK at zero tolerance:
  16,224 rows, including 16,208 found queries, match CSPICE in converted
  ticks, found status, returned clock, rotation and angular velocity.
- Existing scalar acceptance, 42 ET/tick integration references and 32,622
  encoded-tick CK comparisons pass in the developing Geocalc checkout.
  Its complete 420-row frame test still has 10 separate common-parent
  CK-to-child frame failures; these are recorded as geometry-side work,
  not counted as passed time-library validation.
- All twelve required local release gates and the independent review passed
  before the release commit (150 default tests, 163 with MCP and 164 in
  release mode including the type-separation doctest). The validator guards
  run in CI.

The real CK input was `mro_hga_psp_080701_080707.bc` from the official
NASA MRO CK directory (SHA-256
`36c94e631609605a5c0fc6035020580c182d385f87cda2a821ff248aed9504a0`),
with official `mro_v17.tf` (SHA-256
`316dec65e809dd0e4961cfb447d563df104e290457afb06668f10d47292fb23f`),
`MRO_SCLKSCET.00120.tsc` and `naif0012.tls`.

`tools/validate_sclk.py` defaults to bit-exact comparisons in both
directions, uses lossless numeric output, and supplies the same selected
LSK to each engine. Forward tolerance is in seconds; inverse tolerance
is in ticks. These can be relaxed only through explicit separate options.
Malformed, duplicate, missing and non-finite client output is rejected.

Finite-sample engine equality does not establish physical clock accuracy
or guarantee equality for every platform, kernel or input. Test-only
arithmetic fixtures are labeled as artificial inputs; reference outputs
come from CSPICE, not from the Rust implementation. Geocalc source and
its lockfile are not modified by these isolated checks.
