# STKCraft-time 0.1.31

Structured raw NAIF leap tables now have an explicit `NaifUtcContext` with
caller-supplied `NaifDeltet` constants. It preserves original entry order and
defers paired-table validation to native ET-to-JDUTC calculation. This resolves
issue #4's 185 constructor-blocked `SPICE(BADLEAPSECONDS)` cases without changing
the scientific/civil `LeapSecondTable` constructor.

An independent expanded regression precedes the repair. All 26,831 records
match: 22,292 unrounded binary64 outputs and 4,539 exact native error symbols.
The four additional profiles exercise ordering, duplicate dates and invalid
entries inside/outside native's first-140-entry selection. Original captures,
inputs and expectations remain unchanged; the old typed adapter's 8,153
discrepancies and the repaired results are retained.

The existing `TimeContext` API shares the same native arithmetic and retains
its model guards. This additive API accepts structured integral dates/whole
offsets, not arbitrary raw variables or a new MCP input schema. Complete time
or WebGeocalc parity is not claimed. See
[the precise contract and evidence](../reference/NATIVE_JDUTC.md).
