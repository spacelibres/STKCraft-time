# stkcraft-time 0.1.10

Release date: 2026-11-11

This release fixes the four findings in the post-0.1.8 review and adds the
formatting options they require.

## SCLK: clock resets load again

Partition bounds are now validated per partition only: both values must be
finite and `start <= end`. Cross-partition ordering is no longer required.

A spacecraft clock may jump ahead or regress, and that discontinuity is
exactly why a new partition starts, so a kernel such as

```
SCLK_PARTITION_START = ( 100.0 0.0 )
SCLK_PARTITION_END   = ( 1000.0 1000.0 )
```

now parses instead of failing the whole kernel. Encoded ticks↔ET/TAI were
already independent of partitions and stay usable. Mismatched array
lengths and a reversed `start > end` are still errors.

## Formatting: leap seconds and calendars

`format::FormatOptions` carries an optional leap-second table and a
calendar, with new entry points:

- `iso8601_with`, `rfc3339_with`, `spice_calendar_with`, `strftime_with`
- `Formatter::with_options`

With a table, rounding knows the day length:

| Input | Precision | Before | Now |
|---|---|---|---|
| `2016-12-31T23:59:59.9999` | 3 | `2017-01-01T00:00:00.000Z` | `2016-12-31T23:59:60.000Z` |

Without a table the previous behaviour is unchanged and documented: a
86 400-second day is assumed unless the value already has `second >= 60`.

Day carries now use the selected calendar, so Julian `1500-02-28
23:59:59.9999` becomes `1500-02-29T00:00:00.000Z` instead of
`1500-03-01`. `%j`, `%a` and `%A` also follow the selected calendar.

The MCP `format_utc` tool accepts `calendar` and `lsk_path`, and the
`iso8601` field returned by every conversion tool is leap-second aware.

## UT1: reverse conversion at the table edges

The inverse solve now starts from the measured `UT1 - UTC` value instead
of a fixed 32 s offset, and is clamped to the interval that the
interpolation actually supports: the first sample day up to the start of
the final sample day.

A table covering MJD 41684..41686 with `UT1 - UTC = 0.8 s` therefore
round-trips `1973-01-03T23:59:59 UTC`. The final sample day itself stays
out of range, and that boundary is now covered by a test.

## LSK: assignment versus accumulation

`DELTET/DELTA_AT` follows NAIF text-kernel rules: `=` replaces the
accumulated table and `+=` appends to it. A kernel that restates the full
leap-second list in a second data block parses correctly instead of
reporting duplicate dates. Any other operator is a parse error.
