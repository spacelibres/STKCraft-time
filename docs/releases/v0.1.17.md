# stkcraft-time 0.1.17

Release date: 2026-11-11

This release introduces explicit time contracts for SPICE-compatible
geometry and scientifically selected TDB models. Existing public
conversion functions remain available with their previous behavior.

## Default NAIF contract

`contract::TimeContext::new(&lsk)` selects NAIF ET and returns `NaifEt`,
which is distinct from scientific `IauTdb`. No implicit conversion or
automatic scientific fallback is provided. The context exposes selected
LSK constants, entry dates, source and future policy for recording with
the caller's input-file identities.

Checked UTC conversion follows the pinned N0067 TTRANS day-before/day-of
anchors and UNITIM operation order; numeric TAI uses the corresponding
UNITIM entry point. These representations can have different rounding.
The implementation is verified using independent CSPICE outputs, not
hard-coded result corrections. Inverse conversion rejects non-finite
values, integer overflow and civil years outside the calendar's i32
representation instead of returning wrapped dates.

## Explicit scientific contract

`ScientificContext` realizes TT through TAI plus exactly 32.184 seconds,
independently of mutable LSK constants. It returns separately identified
geocentric or observer-dependent SOFA/ERFA TDB results. Observer-dependent
terms require supplied UT1 fraction, east-positive longitude and
cylindrical observer coordinates in kilometres.

Scientific evaluation uses split dates and an explicit inclusive
1950-01-01 through 2050-01-01 model guard. Integer epoch checks preserve
nanosecond boundary decisions. Independent PyERFA observer vectors cover
the model interval, multiple UT1 phases, longitudes and observer positions.
The original ERFA license is retained in distributed attribution.

TT(BIPM), IERS subdaily UT1 corrections, full Earth-orientation
transformations and spacecraft proper time are not implemented by these
APIs. There is no universal nanosecond physical accuracy claim.

## Integration and validation

See [Time contracts](../TIME_CONTRACT.md) for units, model choices,
reproducibility and separate engine/application acceptance criteria.
`tools/validate_geocalc_time.py` builds an isolated client of a developing
Geocalc checkout and compares three independently referenced paths:
equal-ET geometry, UTC-to-ET geometry, and numeric-TAI geometry. It records
source and kernel hashes and rejects missing/non-finite results or
violated component budgets. It does not rewrite Geocalc's source or lock.

Release checks cover default/MCP features, release mode, Clippy,
Rust 1.75, no_std wasm32/thumbv7em targets and rustdoc. Scientific
reference cases and the integration validator are additional checks;
numerical agreement is not mission certification or a physical error bound.

Verified before release:

- All twelve required local release gates passed.
- 910 independent CSPICE N0067 UTC vectors match bit for bit.
- 724 independent ERFA observer TDB vectors pass; existing geocentric
  references and the checked contract regressions also pass.
- The developing Geocalc checkout passed 5,460 state comparisons with
  DE440s. Equal-ET and UTC paths matched exactly in this finite sample;
  the numeric-TAI path had zero ET difference, at most 3.73e-9 km
  position-component difference and 8.88e-16 km/s velocity-component
  difference. The acceptance limits remained 1e-6 km, 1e-10 km/s and
  1e-6 seconds, respectively. DE442s also passed the 42-row default set.
- Both oracle CSV files regenerate byte for byte from independent engines.

These are reproducible numerical comparisons for the tested inputs,
not a claim that every epoch, kernel or scientific correction is covered.
