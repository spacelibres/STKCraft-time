# stkcraft-time 0.1.27

Release date: 2026-11-12

Kernel-date fractional seconds now follow N0067 TPARSE's exact arithmetic
order. The parser previously grouped the entire time of day before adding
the day offset, producing a one-ULP error for seven independently captured
inputs. Native day, hour, minute and second terms are now accumulated in
their original order. All public signatures remain unchanged.

The regression was observed failing for all seven values before the repair.
Original native binary64 expectations are retained without tolerances or
rounding. See [the numerical evidence](../reference/KERNEL_DATE_EXACT.md)
and [issue #1](https://github.com/spacelibres/STKCraft-time/issues/1).

This arithmetic repair does not expand the literal grammar. The 99 native-valid
unsupported inputs in [issue #2](https://github.com/spacelibres/STKCraft-time/issues/2)
remain an explicit integration gap. Complete TPARSE or WebGeocalc conformance
is not claimed. Unsupported input remains an error, never a default epoch.

The complete repository verification commands, main CI, tag CI, release
artifacts, crates.io and docs.rs must pass before publication is accepted.
