# stkcraft-time 0.1.23

Release date: 2026-11-12

This release adds a build-time guard that keeps the public API index in
sync with the source. There is no library, kernel-format or numerical
change.

## The problem it prevents

The 0.1.22 audit found the `docs/API.md` index missing 28 public items,
because nothing connected the source to the guide. Manual review is how that
happens; a test is how it stops happening.

## The guard

`tests/api_index.rs`:

- parses every `pub fn`, `pub struct`, `pub enum`, `pub const`, `pub type`
  and `pub trait` in `src/*.rs`;
- parses the same declarations from the `## 14. Public API index` section of
  `docs/API.md`;
- ignores `pub(crate)` items and anything after `#[cfg(test)]` in a source
  file;
- fails with a sorted list of the offending names:

```text
docs/API.md index is out of sync with the source.
missing from docs/API.md (1):
  parse_lsk
listed in docs/API.md but absent from src (0):
```

It runs as part of `cargo test` and therefore in CI.

## Verified in both directions

- Deleting one line from the index makes the test fail and names
  `parse_lsk`.
- Restoring the line makes it pass again.
- Adding a `pub` item without documenting it fails the same way.

## Documentation

- The `## 14. Public API index` heading states that the list is enforced.
- `CONTRIBUTING.md` requires an index entry for every public item.

## Verification

- 153 tests by default, 166 with the `mcp` feature, all passing
- `cargo fmt --all -- --check`, clippy with `-D warnings` (both feature
  sets), `no_std`, `wasm32-unknown-unknown`, `thumbv7em-none-eabi`
- release build and release tests, MSRV 1.75, rustdoc with `-D warnings`
- `tests/version_sync.rs` confirms every documented version is `0.1.23`
- `tests/api_index.rs` reports 182 public names in both the source and the
