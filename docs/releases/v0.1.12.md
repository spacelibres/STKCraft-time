# stkcraft-time 0.1.12

Release date: 2026-11-11

This release fixes the last formatting boundary found in the 0.1.10
review. It also publishes the crate to crates.io for the first time.

## Leap-second day lengths apply only to 23:59

`FormatOptions` decided the largest expressible second from the length of
the day, but applied it to every minute of that day. On a
86 401-second day that produced a `:60` second at midday.

Only the final minute of a day can gain or lose a second, so the day
length now applies only when `hour == 23 && minute == 59`. Every other
minute ends at `59.999`.

| Input (precision 3, bundled LSK) | Before | Now |
|---|---|---|
| `2016-12-31 12:34:59.9999` | `12:34:60.000` | `12:35:00.000` |
| `2016-12-31 23:58:59.9999` | `23:58:60.000` | `23:59:00.000` |
| `2016-12-31 23:59:59.9999` | `23:59:60.000` | `23:59:60.000` |

The symmetric case is fixed too: on a shortened (86 399-second) day the
ordinary minutes no longer end at `:58.999`; only `23:59:58.9999` carries
into the next day.

This affects the library formatters (`iso8601_with`, `rfc3339_with`,
`spice_calendar_with`, `strftime_with`) and the MCP `format_utc` tool.
Without a leap-second table nothing changes.

## Tests

- `rounding_onto_a_leap_second_uses_the_day_length` now covers midday,
  `23:58`, and `23:59` on a leap-second day.
- `negative_leap_second_shortens_only_the_last_minute` uses a synthetic
  shortened day.
- `format_utc_rounds_onto_a_leap_second` checks the MCP path for both
  `23:59` and midday.
