# stkcraft-time 0.1.16

Release date: 2026-11-11

This release fixes audit findings in historical UTC, spacecraft clock
domains and incomplete leap-second kernels. It also corrects accuracy
and data-provenance documentation. Public function signatures are retained.

## Correct historical UTC adjustment boundaries

SOFA mode now accepts positive fractional mini-leaps, rejects labels
removed by negative adjustments, and applies the historical UTC day rate.
For example, `1971-12-31T23:59:60.05` remains on December 31 when converted
through TAI, rather than being rejected or relabeled as the next day.
Split integer epoch arithmetic avoids losing fractional precision in
the inverse. Formatting uses the fractional final-minute limit directly.

Independent PyERFA vectors cover every historical model transition and
both sides of positive/negative adjustments. The generator records its
upstream revision and required PyERFA version; expected data is not
generated by this crate's implementation.

SOFA's historical rate/mini-leap convention can have overlaps/gaps of a
few nanoseconds at day ends. The inverse assigns actual midnight to the
new date and returns `UtcOutOfRange` for unrepresentable negative gaps.
No universal exact historical round-trip or physical zero-error guarantee
is claimed.

## Reject invalid kernel inputs

Encoded SCLK conversions now enforce the cumulative duration of declared
partitions, including clock resets and integral rounding of readouts.
Negative ticks, ticks before the first coefficient and ticks beyond the
declared domain fail instead of returning extrapolated mission times.
Valid extrapolation within the last partition remains available.
Partition-aware field/string conversion is still outside this release.

Text-kernel decimals now follow NAIF NPARSD arithmetic, including its
exponent-scaling order. A one-interval binary64 parsing difference at an
official JUICE coefficient boundary previously selected the wrong segment
and changed ET by about 0.666 seconds. Independent PRSDP fixtures now
guard this behavior; reference kernels are identified by SHA-256.

LSK parsing requires all `DELTET` constants. An incomplete kernel now
returns `LskMissing` with the missing variable; the MCP server reports a
tool error. Compiled-in nominal constants no longer hide missing data in
a caller-supplied kernel. Explicitly constructed tables remain available
through `LeapSecondTable::new`.

## Accuracy and scope

The compact two-term TDB model is attributed to NASA HEASARC and is no
longer advertised as an unconditional accuracy improvement over NAIF.
The 787-term IAU/SOFA model remains a separate geocentric API.

UT1 remains leap-aware daily EOP interpolation. Subdaily ocean-tide and
libration corrections, observer-dependent relativistic transformations
and uncertainty propagation are not introduced by this release.

## Verification

Release gates include both feature sets, debug and release tests,
Clippy with warnings denied, Rust 1.75, rustdoc, and wasm32/thumbv7em
no_std builds. Independent comparisons use official NASA MRO, ESA JUICE
and IERS data, plus CSPICE/ERFA references. Numerical agreement with an
engine is distinct from physical accuracy or mission certification.

Measured on the release checkout:

- 122 tests with default features; 135 with MCP, including release mode.
- All twelve commands required by `AGENTS.md` passed.
- 800 unique numeric token reference cases match CSPICE PRSDP bit for bit.
- Historical UTC fixtures reproduce byte for byte from PyERFA 2.0.1.5.
- NASA MRO: 10,427 encoded-tick samples, including coefficient neighbors
  and domain endpoints; maximum CSPICE difference `9.313e-10 s`.
- ESA JUICE: 10,286 samples with the same boundary coverage; maximum
  CSPICE difference `9.313e-10 s`.
- IERS: 20,037 daily table values reproduce exactly; 40,072 interpolation
  samples agree with Astropy to `1.110e-16 s`.
- Live NASA WebGeocalc: four UTC/ET samples agree to `2.847e-7 s`, within
  the service's output rounding.

The mission kernels were
[`MRO_SCLKSCET.00120.tsc`](https://naif.jpl.nasa.gov/pub/naif/MRO/kernels/sclk/MRO_SCLKSCET.00120.tsc)
and
[`juice_step_250412_v01.tsc`](https://spiftp.esac.esa.int/data/SPICE/JUICE/kernels/sclk/juice_step_250412_v01.tsc).
Their hashes are recorded in `tests/golden/naif_numbers.csv`. Reproduce
the boundary comparisons with `tools/validate_sclk.py --sclk <kernel>
--id <clock-id> --samples 10000`; the clock IDs are `-74` and `-28`.
